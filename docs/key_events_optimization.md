# 关键事件优化方案

## 优化背景

用户反馈：`key_event`不应该每年都有，只在对人生有关键影响的事件时才生成，避免存储压力和无用数据。

## 优化前的问题

1. **过度生成事件**：原本的逻辑在很多年龄都会生成事件
2. **存储压力**：每年一个事件会产生大量无用数据
3. **用户体验**：太多琐碎事件影响游戏体验

## 优化方案

### 关键事件生成策略

**只在真正的人生关键节点生成事件：**

- 6岁：开始上小学
- 12岁：升入中学
- 18岁：成年/高中毕业
- 22岁：大学毕业/初入职场
- 30岁：三十而立
- 40岁：不惑之年
- 50岁：知天命
- 60岁：临近退休
- 70岁：古稀之年

### 代码优化点

1. **shouldGenerateKeyEvent()方法**：
   - 移除30%随机概率生成
   - 只在明确的关键年龄节点返回true
   - 大幅减少事件生成频率

2. **AI提示词优化**：
   - 明确说明大多数年龄推进无需事件
   - 强调只在重要节点生成关键事件
   - 减少AI过度生成事件的倾向

3. **模板事件优化**：
   - 为每个关键年龄节点定制专门的事件描述
   - 提高事件的意义和价值
   - 移除通用的年龄事件模板

## 优化效果

### 存储优化
- **事件数量减少**：从原来可能80+个事件减少到9个关键事件
- **存储压力**：减少约90%的事件存储
- **查询性能**：事件历史查询更快

### 用户体验
- **更有意义**：每个事件都是人生重要节点
- **清晰简洁**：避免信息过载
- **专注重点**：突出人生关键决策

### 技术架构
- **降级逻辑**：保持原有的降级策略
- **AI集成**：保持统一的AI调用机制
- **向后兼容**：不影响现有的API接口

## 实现细节

```go
// 关键年龄节点（共9个）
keyAges := []int{6, 12, 18, 22, 30, 40, 50, 60, 70}

// 其他年龄不生成关键事件
return false
```

## 总结

通过这次优化，游戏系统变得更加高效和有意义：
- 显著减少存储压力
- 提升用户体验
- 保持系统性能
- 突出人生重要节点

这种"少而精"的事件设计更符合人生模拟游戏的核心理念。
